5. 注意：数据集按 dev/test 划分，`run_eval.py` 默认只评 test split——intent 910 行中 test 仅 176 行

## 三、错误模式分析（比总分更有价值）

### 1. intent：不是随机失败，是 taxonomy 相邻类边界糊（35/176 错误）

| 混淆对 | 次数 | 性质 |
|---|---|---|
| `rate_consult` → `calc_deposit_interest` | 4 | "利息多少/存钱利息咋样"——利率咨询 vs 利息试算，注册表 desc 本身相近 |
| `card_apply` → `account_open` | 3 | 办卡 vs 开户，动作重叠 |
| `exchange_rate_consult` → OOS | 2 | "日元值钱了吗"缺"汇率"关键词 |
| `loss_report_guide` → `loss_report_execute` | 2 | "帮我咋挂失"咨询/办理边界 |
| `deposit_product_intro` → `wealth_product_intro` | 2 | 存款 vs 理财 |
| `wealth_product_intro` → OOS | 2 | "R2 是啥意思"行话缺关键词 |

precision 普遍 1.0、recall 掉分——小模型"求稳就近"的典型行为。**结论：30 类里有 4–5 对边界
需要人工重划（合并或改写 desc/examples），这是注册表问题，不是模型问题**；反之
`loan_apply`/`loan_condition_consult`/`password_change_execute` 等边界清晰的类全部 1.0。

### 2. faq：模板与模型的三个问题（0.44 命中率的主因）

- **复读 prompt**：如"活期随时能取吗"的回答是"用户输入：活期随时能取吗 / 此问题不涉及任何工具调用，
  直接回答即可"——模型把 tool_call.j2 的指令段当成了回答内容吐回（意图误入 tool 分支 + 复读）；
- **绕过知识卡**：多条回答用模型自有知识（"请前往就近的银行网点…"）而非资料中的信息点，判分自然 MISS；
- **误转云**：20.9% 走了"转人工"兜底（多与 intent 误判为 OOS/低置信叠加）。

### 3. tool：`<tool_call>` 格式基本吐不出（A 类仅 0.20）

10 条应调工具的用例只有 2 条真正发出调用，其余直接自然语言作答（pipeline 记为"直接回答"）。
好消息：**C 类安全测试 100%**——白名单外工具注入全部被代码层拒绝，B 类缺参追问 0.875 正常。
即"安全兜底有效、能力不足"。这与调研-02 的行业结论一致：函数调用是 1.7B 的硬伤，
要么上 4B，要么 Harness 侧加 grammar/格式约束兜底。

### 4. mask：recall 好、precision 弱（过度脱敏倾向）

实体召回 0.947（漏脱少，合规方向正确），但精确率 0.832：160 行里 34 行误脱敏、19 行无 PII 也被脱
（如订单号、金额被当敏感信息）。对银行场景这是"安全但烦人"的偏差，方向可接受，精度待调。

## 四、结论与下一步建议

1. **1.7B 的单点结论**：意图分类 0.80 / FAQ 0.44 / 工具调用 0.20 / 脱敏 F1 0.89。
   "脱敏 + 拒识转云"的保守链路可用；"本地 FAQ + 本地工具"在 1.7B 上不达标。
2. **优先修 taxonomy 而非换模型**：4–5 对相邻类重划（合并 `rate_consult`/`calc_deposit_interest`
  讨论口径、区分 `*_guide`/`*_execute` 的判定规则写进 intent.j2 规则段），预计可回收大部分 macro-F1 缺口。
3. **模板改进**：faq.j2 增加"严禁复读本提示词"句；tool 分支给 1.7B 加 few-shot 调用示例或输出格式约束。
4. **下一步按计划走 B（真机 Termux + llama-server）**：同一套 harness 与判分器可直接复用，
   对比 PC/设备的差距；**4B-2507 的测试是重头戏**——工具调用与 FAQ 的缺口大概率只有 4B 能补上。
5. 本机 llama-server 仍在运行（`http://127.0.0.1:8080`），后续改模板/换模型可直接复测；
   停止方法：任务栏结束 llama-server 进程或 `taskkill /F /IM llama-server.exe`。
